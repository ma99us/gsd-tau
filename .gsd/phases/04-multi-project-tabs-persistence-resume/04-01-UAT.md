# S01: Registry Store and Schema Types — UAT

**Milestone:** M004
**Written:** 2026-07-21

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: This slice is a persistence-layer library with no browser/UI surface. All acceptance criteria are fully exercised by the Vitest test suite which simulates atomic writes, .bak fallback, and mid-write kill scenarios.

## Preconditions

- Node.js and pnpm installed
- `pnpm install` has been run in the project root
- No other process holds a write lock on the test temp directories

## Smoke Test

Run `pnpm test -- registry-store` — all 22 tests must pass.

## Test Cases

### 1. Normal round-trip save and load

1. Instantiate RegistryStore with a temp dataDir
2. Call save() with a RegistryV1 payload
3. Call flush() to bypass the debounce
4. Instantiate a new RegistryStore pointing to the same dir and call load()
5. **Expected:** Loaded registry equals saved registry; version field is 1.

### 2. .bak fallback on corrupt registry.json

1. Instantiate RegistryStore, save and flush a valid registry
2. Overwrite registry.json with invalid JSON
3. Call load() on a new instance
4. **Expected:** Load succeeds using registry.bak; returned registry matches original.

### 3. Mid-write kill simulation (orphaned .tmp)

1. Write a valid registry.bak manually
2. Write a corrupt/partial registry.tmp (simulate killed mid-write)
3. Do NOT rename .tmp → registry.json (orphan it)
4. Call load()
5. **Expected:** Load ignores the orphaned .tmp, reads registry.bak, returns valid registry.

### 4. Version field preserved

1. Save a RegistryV1 with version: 1
2. Reload
3. **Expected:** version field equals 1.

## Edge Cases

### Both registry.json and registry.bak missing or corrupt

1. Point RegistryStore at an empty temp dir
2. Call load()
3. **Expected:** Returns getDefault() — empty RegistryV1 with version: 1, empty arrays.

### Debounce coalescing

1. Call save() three times in rapid succession with different payloads
2. Wait 600ms (past debounce)
3. **Expected:** Only one write occurs; the last payload is persisted.

## Failure Signals

- Any test in registry-store.test.ts fails
- tsc --noEmit reports errors on shared/types.ts imports
- registry.json is written without a .bak sibling after the first save+flush cycle

## Not Proven By This UAT

- Behavior under actual OS-level process kill (tested via simulation only)
- %APPDATA% path resolution on end-user machines (dataDir injection abstracts this)
- Interaction with SessionManager (S02 scope)

## Notes for Tester

Run `pnpm test -- registry-store` and confirm "22 passed". The injectable dataDir means tests run fully in temp directories — no %APPDATA% pollution. flush() must be called in tests to bypass the 500ms debounce.
