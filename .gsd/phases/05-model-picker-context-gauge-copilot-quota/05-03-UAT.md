# S03: Thinking level chip and picker — UAT

**Milestone:** M005
**Written:** 2026-07-21

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: The component is fully unit-tested via Vitest (709 tests); the ThinkingLevelChip and SessionHeaderBar cover all rendering branches, optimistic-update, rollback, and keyboard cycling. A Playwright smoke spec would duplicate the same assertions already proven at unit level.

## Preconditions

- `pnpm tsc --noEmit` exits 0.
- `pnpm test` reports 709 tests passed (all 29 files green).
- A live Electron session is open with a reasoning model (e.g. `anthropic/claude-sonnet-4-5` or any model where `ModelInfo.reasoning === true`).

## Smoke Test

Open a session with a reasoning model. Confirm the session header displays `💡 medium ▼` (or the current thinking level).

## Test Cases

### 1. Chip renders on reasoning model

1. Open a session where `getState().modelInfo.reasoning === true`.
2. Inspect the session header bar.
3. **Expected:** `💡 {currentLevel} ▼` chip is visible between the model chip and cost line.

### 2. Chip absent on non-reasoning model

1. Switch to a non-reasoning model (e.g. a provider model where `reasoning === false`).
2. **Expected:** The thinking-level chip and its trailing separator are absent from the header.

### 3. Picker opens and switches level

1. Click the `💡 medium ▼` chip.
2. **Expected:** Dropdown lists all 7 levels: auto, min, low, medium, high, xhigh, max. Current level is highlighted.
3. Click `high`.
4. **Expected:** Chip immediately updates to `💡 high ▼`. `window.gsd.setThinkingLevel` is called; on success the level persists.

### 4. Rollback on failure

1. With DevTools open, mock `window.gsd.setThinkingLevel` to return `null`.
2. Click the chip and select a different level.
3. **Expected:** Chip briefly shows the new level then reverts to the original. `console.error` fires in the renderer.

### 5. Ctrl+Shift+T cycles level

1. Focus any part of the session window with a reasoning model active.
2. Press `Ctrl+Shift+T`.
3. **Expected:** Thinking level advances to the next level in the `RPC_THINKING_LEVELS` array (wraps from max → auto). Chip updates immediately.

## Edge Cases

### Level already at max

1. Set thinking level to `max`.
2. Press `Ctrl+Shift+T`.
3. **Expected:** Level wraps to `auto`.

### setThinkingLevel returns null (IPC error)

1. Kill the pi RPC process mid-call.
2. Pick a new level from the dropdown.
3. **Expected:** Chip rolls back to previous level; renderer logs `console.error`.

## Failure Signals

- Chip absent on reasoning model → `isReasoningModel` guard or `thinkingLevel` state not populated.
- Level does not persist after next turn → `SET_THINKING_LEVEL` handler or `set_thinking_level` RPC call failing silently.
- Duplicate key handlers → Ctrl+Shift+T fires multiple level changes at once.

## Not Proven By This UAT

- Live RPC round-trip to a real pi session (requires a running pi process).
- Correct pi `set_thinking_level` RPC payload format (covered by contracts type-check, not runtime UAT).
- Cross-session isolation (each session's thinking level stored independently).

## Notes for Tester

The optimistic-update / rollback path is easiest to test via DevTools console: `window.gsd.setThinkingLevel = async () => null`. All unit-level branches are already green in the 709-test suite.
