# S05: Shutdown Cancellation and Playwright Tests — UAT

**Milestone:** M003
**Written:** 2026-07-20

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: The slice's primary deliverable is an automated Playwright test suite. Running `pnpm test:e2e -- ui-requests` is the canonical acceptance proof. The shutdown-cancel path is covered by both the Playwright spec (test case 7) and Vitest unit tests.

## Preconditions

1. `pnpm build` has been run to produce `out/main/index.js` (required by Electron Playwright tests).
2. Electron binary is present (`pnpm install` completed including Electron download).
3. No orphaned gsd/Electron processes from prior runs.

## Smoke Test

Run `pnpm test -- shutdown-cancel` — all 5 tests must pass in under 2s.

## Test Cases

### 1. Shutdown-cancel unit tests

1. Run `pnpm test -- shutdown-cancel`
2. **Expected:** 5/5 tests pass; output shows "cancelled:true sent" log lines for each blocker.

### 2. Full Playwright e2e suite

1. Run `pnpm build`
2. Run `pnpm test:e2e -- ui-requests`
3. **Expected:** All 7 test cases pass — select, confirm, input, editor, notify+setStatus, queue depth, and shutdown-cancel.

### 3. Select modal (cases 1a + 1b)

1. Mock-pi emits `extension_ui_request` with method `select`, options `["A","B","C"]`, `multiple: false`, then `multiple: true`
2. Playwright selects an option and submits
3. **Expected:** Mock records `{ value: "A" }` (single) and `{ value: ["A","B"] }` (multi) responses.

### 4. Confirm modal (cases 2a + 2b)

1. Mock-pi emits confirm request; Playwright clicks Yes, then No
2. **Expected:** Mock records `{ value: true }` then `{ value: false }`.

### 5. Input modal (cases 3a + 3b)

1. Mock-pi emits input request (plain), then secure (password)
2. Playwright types text and submits
3. **Expected:** Mock records typed text; secure input masks display.

### 6. Editor modal (cases 4a + 4b)

1. Mock-pi emits editor request; Playwright submits content, then cancels
2. **Expected:** Mock records submitted content; cancel sends `{ cancelled: true }`.

### 7. Non-modal render (case 5)

1. Mock-pi emits `notify` and `setStatus` requests
2. **Expected:** App auto-acks with `{ value: '' }`; no modal appears; mock records acks.

### 8. Queue depth badge (case 6)

1. Mock-pi emits two simultaneous blockers
2. **Expected:** Queue depth badge shows "2" in the UI.

### 9. Shutdown-cancel e2e (case 7)

1. Mock-pi emits a confirm modal; Playwright triggers app quit before responding
2. **Expected:** Mock pi receives `{ cancelled: true }` before the process exits.

## Edge Cases

### Orphaned processes

After 20 runs of `pnpm test:e2e -- ui-requests`, no orphaned Node child processes (named `mock-pi-server`) should remain.

**Expected:** `Get-Process node | Where-Object CommandLine -like "*mock-pi*"` returns empty.

## Failure Signals

- Any Playwright test reporting timeout on modal appearance: check `GSD_TAU_MOCK_PI` env var is forwarded to Electron.
- `pnpm build` failure: check TypeScript errors in modified files.
- `cancelled:true` not received by mock: check pre-shutdown hook registration in handlers.ts.

## Not Proven By This UAT

- Live pi integration (tests use mock-pi-server, not a real pi binary).
- 20-run process-leak check (manual verification step).
- Windows toast timing (covered in S02 UAT).

## Notes for Tester

`pnpm build` is required before running e2e tests — the Playwright spec launches a compiled Electron app. The GSD_TAU_MOCK_PI env var bypass in client-factory.ts replaces real pi with mock-pi-server.cjs for all e2e test runs.
