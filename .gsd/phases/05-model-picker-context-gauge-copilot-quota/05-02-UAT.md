# S02: Model picker dropdown — UAT

**Milestone:** M005
**Written:** 2026-07-21

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: The model picker is renderer-side logic wired to IPC stubs. All integration paths (optimistic update, rollback, grouped display, TTL cache) are covered by the 672-test vitest suite. A Playwright e2e smoke test targeting the picker is the remaining live-runtime check.

## Preconditions

- Dev server running: `pnpm dev` → `http://localhost:5173` (Electron renderer served by Vite)
- A valid project open with at least one active session
- `window.gsd.getAvailableModels` resolves with ≥2 models across ≥1 provider

## Smoke Test

Click the model chip in the session header. A dropdown opens listing models grouped by provider. The current model is checked/highlighted.

## Test Cases

### 1. Dropdown opens and shows grouped models

1. Open a project with an active session.
2. Observe the model chip in the session header (e.g. `anthropic/claude-sonnet-4.6`).
3. Click the chip.
4. **Expected:** Dropdown opens. Models are grouped by provider heading. Each model row shows name, context-window size (formatted), and a `reasoning` badge where applicable. Current model is visually indicated.

### 2. Picking a model updates the chip optimistically

1. Open the model picker dropdown.
2. Click a model different from the current one (e.g. `openai/gpt-4o`).
3. **Expected:** Dropdown closes. Model chip updates immediately to the selected model without waiting for a round-trip. `window.gsd.setModel` is called with the new model ID.

### 3. Confirmation on next execution_complete

1. After selecting a new model, send a message.
2. Wait for `execution_complete`.
3. **Expected:** Model chip continues to show the selected model (confirmed via `get_state` response).

### 4. Rollback on setModel error

1. Simulate a `setModel` rejection (e.g. disconnect session or mock an error).
2. Click the model chip and select a new model.
3. **Expected:** Chip reverts to the previous model value after the rejection. No crash or blank chip.

### 5. 60-second TTL cache

1. Open the picker; note which models appear.
2. Close and reopen within 60 seconds.
3. **Expected:** No additional IPC call is made; same model list appears instantly.
4. Wait 60+ seconds, reopen.
5. **Expected:** `getAvailableModels` IPC is called again and list refreshes.

## Edge Cases

### Empty model list

1. `getAvailableModels` returns `[]`.
2. Open the picker.
3. **Expected:** Dropdown shows a graceful empty state (no crash, no blank menu).

### Single provider

1. All returned models belong to one provider.
2. Open the picker.
3. **Expected:** One provider group heading is shown; list renders correctly.

## Failure Signals

- Model chip shows `undefined` or blank after selection
- Dropdown does not open on click
- Console error from `setModel` rejection without rollback
- Selecting a model and the chip still shows the old value after 2+ seconds with no error

## Not Proven By This UAT

- Live Electron integration (IPC to real pi process)
- That `get_state` after the next turn confirms the new model (requires live session)
- Copilot models or provider-specific auth gating

## Notes for Tester

The 672-unit vitest suite covers optimistic update, rollback, TTL cache, grouping, and formatContextWindow. The UAT test cases above are for manual or Playwright-assisted verification in the running Electron app. The `reasoning` badge relies on the `reasoning` property in `ModelInfo` from the RPC contract — check the contract if badge is absent for a known reasoning model.
