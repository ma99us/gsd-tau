# S05: Pi slash commands in palette and regression check — UAT

**Milestone:** M006
**Written:** 2026-07-22

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All acceptance criteria for the pi-commands integration are covered by the vitest unit-test suite (usePiCommands, CommandPalette, useAppCommands). The live end-to-end flow (opening palette, seeing a /gsd skill, pressing Enter) requires a running pi session wired via RPC and is validated by the existing unit tests that mock window.gsd.getCommands and window.gsd.prompt. The Playwright smoke suite covers the keyboard/overlay integration from S04.

## Preconditions

- `pnpm vitest run` passes (exit 0)
- For live smoke: `pnpm dev` running, a pi session open in the app with a project that has the /gsd skill registered

## Smoke Test

Run `pnpm vitest run renderer/hooks/usePiCommands.test.ts renderer/components/CommandPalette.test.ts` — all 78 tests pass.

## Test Cases

### 1. usePiCommands cache hit/miss

1. Construct hook with a mock fetcher that returns `[{ name: 'gsd', type: 'skill', description: 'GSD skill' }]`
2. Call `fetch()` twice within the 60 s TTL window
3. **Expected:** fetcher called exactly once; second call returns cached result

### 2. pi commands appear in palette with badge

1. Open `CommandPalette` with `usePiCommands` mocked to return `[{ name: 'gsd', type: 'skill', description: 'GSD skill' }]`
2. Type `/gsd` in the filter input
3. **Expected:** list shows an item with label `/gsd`, badge `skill`, and description `GSD skill`

### 3. Selecting a pi command dispatches prompt

1. Open palette, select the `/gsd` item, press Enter
2. **Expected:** `window.gsd().prompt` called with `'/gsd'`; palette closes

### 4. Regression — full suite

1. Run `pnpm vitest run`
2. **Expected:** 39 files, ≥1002 tests, exit 0

## Edge Cases

### null sessionId no-op

1. Render `usePiCommands` with `sessionId = null`
2. Call `fetch()`
3. **Expected:** fetcher not called; result is empty array

### getCommands RPC error

1. Mock `window.gsd.getCommands` to reject
2. Call `fetch()`
3. **Expected:** hook returns empty array; no cache entry written; no uncaught exception

### pi command ID collision prevention

1. Check that built-in app command IDs (e.g. `compact-context`) are never prefixed with `pi:`
2. Check that pi commands have IDs like `pi:/gsd`
3. **Expected:** no collisions in merged command list

## Failure Signals

- `pnpm vitest run` exits non-zero or test count drops below 1002
- Badge or description missing from palette list item in the running app
- `window.gsd().prompt` not called when a pi command is selected

## Not Proven By This UAT

- Live RPC round-trip with a real pi process (requires running session)
- Commands registered by extensions other than the built-in skill/prompt/command types
- Latency of get_commands over a slow or remote pi session

## Notes for Tester

The `usePiCommands` hook is intentionally imperative — it only fetches when `fetch()` is explicitly called (on palette open), not on mount. If testing manually, the palette must be opened to trigger the IPC call.
