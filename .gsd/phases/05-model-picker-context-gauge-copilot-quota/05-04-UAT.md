# S04: Context window gauge with compact button — UAT

**Milestone:** M005
**Written:** 2026-07-21

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All acceptance criteria (colour transitions, popover breakdown, Compact button, fallback, IPC wiring) are covered by automated unit tests (pnpm test) and tsc type checking. No browser navigation required for this header-widget slice.

## Preconditions

- `pnpm tsc --noEmit` exits 0
- `pnpm test` passes all 747 tests

## Smoke Test

Run `pnpm test -- --reporter=verbose ContextGauge` and confirm all ContextGauge tests pass.

## Test Cases

### 1. Colour coding thresholds

1. Render ContextGauge with fill < 60%
2. **Expected:** bar class includes green colour token

### 2. Amber tier

1. Render ContextGauge with fill between 60% and 85%
2. **Expected:** bar class includes amber colour token

### 3. Red tier at 85%+

1. Render ContextGauge with fill ≥ 85%
2. **Expected:** bar class includes red colour token

### 4. Fallback display

1. Render ContextGauge with unknown contextWindow (null)
2. **Expected:** renders raw "Context Nk tokens" text, no bar

### 5. Popover breakdown

1. Click gauge button
2. **Expected:** popover opens showing input, output, cacheRead, cacheWrite, total token breakdown

### 6. Compact button delegation

1. Click Compact button
2. **Expected:** window.gsd.compact(sessionId) called; isCompacting prevents duplicate calls

### 7. COMPACT IPC null-on-error

1. SessionManager.compact() throws
2. **Expected:** IPC handler returns null; renderer receives null (no unhandled rejection)

## Edge Cases

### Unknown contextWindow

1. Pass contextWindow: null into ContextGauge
2. **Expected:** fallback "Context Nk tokens" shown, no percentage bar

### Duplicate compact calls

1. Trigger Compact while isCompacting is true
2. **Expected:** second call is blocked; only one RPC in flight

## Failure Signals

- Any ContextGauge test failure in pnpm test output
- tsc --noEmit reporting type errors in ContextGauge.tsx or handlers.ts

## Not Proven By This UAT

- Live cost_update event integration in a running Electron app
- Visual appearance of colour transitions in the actual UI

## Notes for Tester

The popover uses an inline controlled-div rather than @radix-ui/react-popover. Keyboard navigation and focus-trap are not implemented — acceptable for Electron desktop v1.
