# S06: Shutdown and Smoke Test — UAT

**Milestone:** M002
**Written:** 2026-07-20

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: The smoke test is a Playwright test suite (`test/smoke.spec.ts`) that exercises the full happy-path programmatically (launch → folder picker → open project → prompt → response → shutdown → leak check). A `runtime-executable` UAT running `pnpm test:e2e` is the appropriate mode; human interaction is not needed once a live LLM provider is configured.

## Preconditions

1. `pnpm build` passes (confirmed — exits 0).
2. A GitHub Copilot or other supported LLM provider is authenticated (`gsd --login` completed, token cached in `%USERPROFILE%\.gsd\auth.json`).
3. Electron binary is installed (`node node_modules/electron/install.js` — confirmed done).
4. The `gsd` binary on PATH resolves to `C:\nvm4w\nodejs\node_modules\@opengsd\gsd-pi\dist\loader.js` (confirmed via `resolve-pi.ts` fix).

## Smoke Test

Run `pnpm test:e2e` once and confirm Playwright reports 1 passed test with no console errors.

## Test Cases

### 1. Full happy-path smoke run

1. Run `pnpm test:e2e`.
2. Playwright launches Electron via `_electron.launch({ args: ['out/main/index.js'] })`.
3. `firstWindow()` + `waitForLoadState('domcontentloaded')` — wait up to 30 s.
4. Folder picker (`[data-testid="folder-picker"]`) becomes visible within 30 s.
5. Session opens for the fixture project directory.
6. App transitions to Idle state; composer input becomes visible.
7. Type `say hello in exactly three words` → press Enter.
8. Assert assistant response text with ≥ 2 words appears within 60 s.
9. App closes cleanly.
10. **Expected:** `Get-Process gsd` returns zero results after close; zero console errors logged.

### 2. 10-consecutive-run stability

1. Run `pnpm test:e2e` ten consecutive times (or `pnpm test:e2e --repeat 10` if configured).
2. **Expected:** All 10 runs report passed; no gsd.exe leaks between runs; no EINVAL / ENOENT errors in output.

## Edge Cases

### Shutdown under load

1. Open app, start a long-running prompt, then close the window immediately.
2. **Expected:** `before-quit` fires, `sessionManager.close()` calls `client.shutdown()`, gsd exits within 3 s; if not, `client.stop()` is called and app exits within 5 s total.

### Binary not found

1. Temporarily unset `GSD_PI_PATH` and rename `gsd.cmd` out of PATH.
2. Launch app and open a project.
3. **Expected:** `ResolvePiError` thrown; error surfaces in renderer as a user-readable message (Phase 11 will add the guided setup screen).

## Failure Signals

- `pnpm test:e2e` reports timeout on folder picker → likely React hydration lag; check `waitForLoadState` timeout or renderer startup error.
- `pnpm test:e2e` reports EINVAL on gsd spawn → `resolve-pi.ts` returned a `.cmd` path instead of `.js`; check `deriveJsFromCmd` logic.
- `Get-Process gsd` returns results after app close → shutdown handler did not fire or `client.stop()` failed silently.
- Console errors logged in Electron renderer → IPC handler not registered; check `registerHandlers(sessionManager)` call in `app.whenReady()`.

## Not Proven By This UAT

- 10-consecutive-run stability requires a live LLM provider — not proven in CI without provider credentials.
- Cross-session isolation (Phase 1 restriction: only one session at a time).
- Windows Task Manager visual confirmation of gsd.exe exit (automated via `Get-Process` check).

## Notes for Tester

The `resolve-pi.ts` fix (JS path instead of .cmd) is the critical change for this slice. If gsd spawn fails, verify the resolved path ends in `.js`, not `.cmd`. The smoke test fixture is created in `os.tmpdir()` to avoid nested-git issues. The 5 s graceful shutdown deadline from T11 means the `Get-Process` leak check polls up to 8 s after `app.close()`.
