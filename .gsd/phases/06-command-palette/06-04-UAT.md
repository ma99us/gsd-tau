# S04: Keyboard shortcut wiring and palette integration — UAT

**Milestone:** M006
**Written:** 2026-07-22

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All wiring is renderer-side event binding. The 1002 unit tests (vitest) cover prop contracts and component integration. A runtime-executable check (`pnpm vitest run`) confirms no regressions. Full browser interaction with the palette is covered by S05 UAT when a live pi session is available.

## Preconditions

- Node dependencies installed (`pnpm install`)
- `pnpm vitest run` exits 0

## Smoke Test

Run `pnpm vitest run` — 38 test files and 1002 tests must all pass.

## Test Cases

### 1. Full unit test suite passes

1. Run `pnpm vitest run` from the project root
2. **Expected:** Exit code 0; 38 test files, 1002 tests — all passed; no skipped or failing tests

### 2. Composer forwardRef contract

1. Import `Composer` and `ComposerHandle` from `renderer/components/Composer.tsx`
2. Create a ref with `React.createRef<ComposerHandle>()`
3. Pass the ref to `<Composer>`
4. **Expected:** ref.current exposes a `focus()` method; calling it focuses the textarea

### 3. ModelPickerDropdown controlled-open

1. Render `<ModelPickerDropdown open={true} onOpenChange={fn} />`
2. **Expected:** Dropdown opens immediately; calling `onOpenChange(false)` closes it

### 4. SessionHeaderBar forcePickerOpen prop

1. Render `<SessionHeaderBar forcePickerOpen={true} />`
2. **Expected:** ModelPickerDropdown opens; resetting to false and back to true re-opens it

### 5. CommandPalette mounted in App.tsx

1. Import `CommandPalette` and `CommandPaletteProps` from `renderer/components/CommandPalette.tsx`
2. **Expected:** Named exports exist and are importable (covered by T03 contract tests)

## Edge Cases

### Ctrl+Shift+K does not trigger composer focus

1. In a rendered SessionView, fire a `keydown` event for Ctrl+Shift+K
2. **Expected:** Composer does NOT receive focus (shiftKey guard prevents it)

### Repeated Ctrl+. presses re-open the model picker

1. Fire Ctrl+. to open model picker
2. Close the picker
3. Fire Ctrl+. again
4. **Expected:** Model picker opens again (setTimeout reset pattern allows re-triggering)

## Failure Signals

- Any test failure in `pnpm vitest run` output
- `Composer.test.ts` suite count drops below 34
- `ModelPickerDropdown.test.ts` suite count drops below 46
- Import errors for `ComposerHandle`, `ComposerProps`, or `isModelCommand` from Composer.tsx

## Not Proven By This UAT

- Live Ctrl+Shift+P triggering in a running Electron app (requires S05 live session)
- Actual focus movement to composer textarea in a real browser context
- Model picker visual open state in a rendered Electron window
- Interaction with live pi session events

## Notes for Tester

The keyboard shortcut wiring is renderer-side only. Observing the shortcuts in a live app requires `pnpm dev` and Electron to be running. The unit tests cover the prop contracts and component composition but not the DOM focus side-effect. S05 will exercise the full keyboard + palette flow with a live pi session.
