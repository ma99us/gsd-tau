# S02: IPC Handler and Windows Notifications — UAT

**Milestone:** M003
**Written:** 2026-07-20

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: S02 delivers IPC handler logic and a toast notification module. Both are fully covered by Vitest unit tests. The toast's visual appearance requires a live Windows desktop session, but functional correctness (debounce, click handler wiring, validation logic) is proven by the injectable test harness. Runtime test execution is the appropriate gate.

## Preconditions

- Node 18+, pnpm installed
- `pnpm install` completed in `D:/Projects/gsd-tau`
- No dev server required — all checks are unit/integration tests

## Smoke Test

Run `pnpm test -- handlers` and confirm 62 tests pass with no failures.

## Test Cases

### 1. respondUI validation and happy path

1. Run `pnpm test -- ipc/handlers`
2. Observe 62 tests pass covering: handler registration, openProject fan-out, getState (including Waiting state), cleanup, validateUiResponse (20 direct unit tests), respondUI (16 IPC integration tests)
3. **Expected:** 0 failures

### 2. Windows toast notification module

1. Run `pnpm test -- notifications`
2. Observe 13 tests pass covering: showBlockerToast fires Notification, debounce suppresses second call within 3s, debounce allows call after 3s, Notification.isSupported()=false skips Notification creation, click handler calls app.focus and window.show
3. **Expected:** 0 failures

### 3. No regression on pre-existing suites

1. Run `pnpm test`
2. **Expected:** only `client-factory.test.ts` failures (15, pre-existing); all other suites green

## Edge Cases

### respondUI against unknown requestId

1. Call respondUI with a valid sessionId but non-existent requestId
2. **Expected:** returns `{ ok: false, error: 'Request not found' }` — does not throw to renderer

### Debounce boundary

1. Fire `showBlockerToast('proj', 'confirm')` at t=0
2. Fire again at t=2s
3. Fire again at t=4s
4. **Expected:** toast 1 fires; toast 2 suppressed; toast 3 fires (debounce window expired)

## Failure Signals

- Any test in `ipc/handlers.test.ts` or `notifications.test.ts` failing
- `validateUiResponse` returning wrong shape for valid input
- `session:ui-request-added` or `session:ui-request-removed` events not emitted to webContents

## Not Proven By This UAT

- Visual appearance of Windows toast on a live desktop (requires interactive session)
- AppUserModelID attribution visible in Start menu (requires installed app)
- End-to-end flow from real pi `extension_ui_request` event through toast to modal (S03)

## Notes for Tester

The 15 failures in `client-factory.test.ts` are pre-existing and unrelated to S02. A manual toast smoke test script exists at `scripts/test-toast.ts` for visual verification on a Windows desktop.
