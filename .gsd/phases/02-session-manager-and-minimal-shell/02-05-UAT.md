# S05: Renderer Chat View — UAT

**Milestone:** M002
**Written:** 2026-07-20

## UAT Type

- UAT mode: browser-executable
- Why this mode is sufficient: The slice delivers a UI chat view; observable acceptance requires launching the Electron app (dev server), picking a folder, and confirming turn rendering and tool card behaviour in the live window.

## Preconditions

- `pnpm dev` starts successfully (Electron window opens)
- A local project directory is available to pick (e.g. `D:/Projects/gsd-tau`)
- pi (`gsd`) is installed on PATH and accessible from the project directory

## Smoke Test

Launch `pnpm dev`, enter a valid project path in the folder picker, click Open, type "hello" in the Composer, press Enter — confirm a streamed assistant response appears in the turn list.

## Test Cases

### 1. Folder picker sets project and enables Composer

1. Launch `pnpm dev` — Electron window opens showing the folder-picker input and Open button.
2. Enter a valid directory path (e.g. `D:/Projects/gsd-tau`) and click Open.
3. **Expected:** Folder picker disappears; Composer textarea becomes active and enabled; no error message shown.

### 2. Sending a message streams an assistant response

1. With project open, type "hello" in the Composer textarea.
2. Press Enter.
3. **Expected:** A user bubble "hello" appears immediately. An assistant turn opens and assistant text streams in incrementally (text_delta events appended). Composer clears after send and re-enables when the turn completes.

### 3. Tool card rendered for tool_use / tool_result

1. With project open, type "read package.json" in the Composer and press Enter.
2. **Expected:** A ToolCard appears in the assistant section showing the tool name ("read") and a 80-char input summary. Card initially shows a pending state. When the tool result arrives, the pending state is replaced with the result text.

### 4. Expand/collapse on ToolCard

1. After a tool card has rendered with a result (step 3 above).
2. Click the tool card.
3. **Expected:** Card expands to show full result content. Click again — card collapses.

### 5. Shift+Enter inserts newline; Enter submits

1. In the Composer, type a partial message.
2. Press Shift+Enter.
3. **Expected:** A newline is inserted into the textarea; the message is NOT sent.
4. Press Enter (without Shift).
5. **Expected:** The multi-line message is sent.

## Edge Cases

### Empty send (Enter with blank Composer)

1. Focus Composer with empty textarea, press Enter.
2. **Expected:** No message sent; turn list unchanged.

### ToolCard with no input content

1. If a tool_use event arrives with an empty or minimal input JSON.
2. **Expected:** ToolCard renders without a chevron/expand control (no expandable content); no crash.

## Failure Signals

- Composer remains disabled after clicking Open with a valid path — session failed to start
- No assistant text appears after sending "hello" — IPC bridge or event pump broken
- ToolCard shows persistent "pending" state and no result — tool_result event not wired to reducer
- JS errors in DevTools console with unhandled promise rejections — event subscription leak

## Not Proven By This UAT

- Multi-turn conversation continuity across page reloads (persistence is Phase 3+)
- Error surfacing when `window.gsd.prompt` rejects — swallowed in Phase 1, deferred
- Tabs or multiple simultaneous sessions (Phase 3)
- Shutdown cancelling the pi child within 3s (S06)

## Notes for Tester

The folder picker is a text input + Open button, not a native OS dialog. pi must be on PATH for the session to start. Pre-existing TypeScript error in `main/session/session-manager.test.ts` is unrelated to S05 and can be ignored.
