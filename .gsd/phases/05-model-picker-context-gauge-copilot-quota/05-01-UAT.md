# S01: Session header: model chip and cost line — UAT

**Milestone:** M005
**Written:** 2026-07-21

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: The header bar is a renderer component wired to IPC channels and pi events. Playwright E2E smoke tests can launch the Electron app, open a session, and assert the header bar elements are visible with correct initial values. The cost_update live-update path is verified by existing unit tests covering the event subscription logic.

## Preconditions

- `pnpm build` succeeds (TypeScript clean, all 614 unit tests pass)
- pi (gsd) is installed and on PATH (`gsd --version` returns ≥ 1.11.0)
- A valid project directory exists to open as a session

## Smoke Test

Open the app, open any project — the session header bar should render with `<provider>/<model-id>  $0.00` within 2 seconds of the session connecting.

## Test Cases

### 1. Header bar renders on session open

1. Launch the app (`pnpm start` or packaged binary)
2. Open an existing project via the [+] flyout
3. Wait for the session to connect (pi process running)
4. **Expected:** A header bar appears below the path header showing a model identifier in the form `provider/model-id` and a cost line reading `$0.00`

### 2. Cost updates after a turn

1. With a connected session, observe the initial `$0.00` cost
2. Send a message to pi and wait for `execution_complete`
3. **Expected:** The cost line increments to a non-zero value (e.g. `$0.01`) reflecting the cumulative cost from the `cost_update` event

### 3. Header bar present in all open sessions

1. Open two different projects in separate tabs/windows
2. Switch between them
3. **Expected:** Each session displays its own independent model chip and cost line; switching tabs does not reset or share cost state

## Edge Cases

### Session not yet connected

1. Open the app while pi binary is unavailable or slow to start
2. **Expected:** Header bar renders with a loading/unknown state (no crash, no `$NaN` or `undefined` visible)

### Null RPC state response

1. If GET_RPC_STATE returns null (session mid-shutdown)
2. **Expected:** Header bar degrades gracefully — shows last known model or placeholder; no React error boundary triggered

## Failure Signals

- Header bar absent from session view (SessionHeaderBar not rendered)
- Cost line shows `undefined`, `NaN`, or `$NaN`
- Console errors relating to ipcRenderer.invoke('GET_RPC_STATE') or 'GET_SESSION_STATS'
- pnpm test exit non-zero

## Not Proven By This UAT

- Model picker interaction (S02)
- Thinking level chip (S03)
- Context gauge live-update accuracy under high token load (S04)
- Copilot quota widget (S05)
- Cross-platform (macOS/Linux) rendering — Windows only for v1

## Notes for Tester

The cost display uses `cumulativeCost` from `RpcCostUpdateEvent` — not a sum of per-turn costs. If cost appears to jump unexpectedly, check whether pi is emitting multiple `cost_update` events per turn (expected) vs. one per message. The header bar always shows the running cumulative total.
