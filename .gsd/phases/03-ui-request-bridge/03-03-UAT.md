# S03: Modal Components — UAT

**Milestone:** M003
**Written:** 2026-07-20

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All modal logic is covered by pure-function unit tests runnable headlessly via vitest. No browser interaction is needed at this stage since modal wiring into the live app (BlockerTracker IPC) is deferred to S04. A runtime test pass is sufficient evidence that all four modals produce correct response shapes.

## Preconditions

- Node.js and pnpm installed
- `pnpm install` complete
- `npx vitest run renderer/components/modals` executable from project root

## Smoke Test

Run `npx vitest run renderer/components/modals` — must exit 0 with 4 files, 58 tests passed.

## Test Cases

### 1. SelectModal single-select response

1. Call `buildSelectResponse(['A','B','C'], ['B'], false)`
2. **Expected:** `{ value: 'B' }`

### 2. SelectModal multi-select response

1. Call `buildSelectResponse(['A','B','C'], ['A','C'], true)`
2. **Expected:** `{ values: ['A','C'] }`

### 3. SelectModal empty selection

1. Call `buildSelectResponse(['A','B'], [], false)`
2. **Expected:** `null` (Confirm button should be disabled)

### 4. toggleOption multi-select toggle

1. Call `toggleOption(['A'], 'A', true)` (deselect)
2. **Expected:** `[]`
3. Call `toggleOption(['A'], 'B', true)` (add)
4. **Expected:** `['A','B']`

### 5. ConfirmModal responses

1. Verify Yes response: `{ confirmed: true }`
2. Verify No response: `{ confirmed: false }`
3. Verify Cancel response: `{ cancelled: true }`
4. **Expected:** All three are distinct

### 6. InputModal secure masking

1. Render InputModal with `secure: true`
2. **Expected:** Input element uses `type=password`; value never logged

### 7. EditorModal Ctrl+Enter detection

1. Call `isEditorSubmitCombo({ key: 'Enter', ctrlKey: true })` → `true`
2. Call `isEditorSubmitCombo({ key: 'Enter', ctrlKey: false })` → `false`
3. **Expected:** Plain Enter does not submit; Ctrl+Enter does

## Edge Cases

### Empty editor content

1. Attempt submit with empty string `""`
2. **Expected:** Rejected (submit disabled)

### Editor newline-only content

1. Submit with `"\n"` or `"\n\n"`
2. **Expected:** Accepted (blank lines are valid)

### SelectModal cancel

1. Trigger cancel (Escape or Cancel button)
2. **Expected:** `{ cancelled: true }` sent

## Failure Signals

- Any test file reports non-zero exit code
- Test count drops below 58
- `buildSelectResponse` returns wrong shape for single vs multi mode

## Not Proven By This UAT

- Live rendering in Electron renderer process
- Integration with BlockerTracker IPC events (deferred to S04)
- Modal queue rendering and FIFO ordering (S04)
- Windows focus trapping in production Electron window
- Accessibility (keyboard navigation) in live browser environment
