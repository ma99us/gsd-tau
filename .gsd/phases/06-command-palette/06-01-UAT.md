# S01: Fuzzy match engine and MRU hook — UAT

**Milestone:** M006
**Written:** 2026-07-22

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: Both deliverables are pure TypeScript modules with no browser runtime dependency. The vitest suite is the complete acceptance gate — it covers all scorer and hook behaviors including the roadmap assertion. No UI or server is involved.

## Preconditions

- Node/pnpm installed; `pnpm install` has been run
- `renderer/hooks/fuzzyMatch.ts`, `renderer/hooks/fuzzyMatch.test.ts`, `renderer/hooks/useMRU.ts`, `renderer/hooks/useMRU.test.ts` present

## Smoke Test

Run `pnpm vitest run renderer/hooks/fuzzyMatch.test.ts renderer/hooks/useMRU.test.ts` — both files should report all tests passed with exit 0.

## Test Cases

### 1. Roadmap assertion — fuzzyScore ordering

1. Run `pnpm vitest run renderer/hooks/fuzzyMatch.test.ts`
2. **Expected:** All 15 tests pass. The test covering `fuzzyScore('cp','compact context') > fuzzyScore('cp','open project')` passes (open project returns -Infinity).

### 2. MRU round-trip through injectable storage

1. Run `pnpm vitest run renderer/hooks/useMRU.test.ts`
2. **Expected:** All 21 tests pass, including tests that record entries, verify they appear at the head of the list, verify deduplication (re-recording moves entry to front), and verify max-length cap evicts oldest entries.

## Edge Cases

### Non-subsequence query

- fuzzyScore('xyz', 'compact context') returns -Infinity
- **Expected:** Covered by test suite; callers can filter with `score !== -Infinity`

### MRU deduplication

- Recording the same key twice should not create two entries — the second record moves it to front
- **Expected:** Covered by test suite

## Failure Signals

- Any test file reporting failures or non-zero exit code
- Missing files: `renderer/hooks/fuzzyMatch.ts` or `renderer/hooks/useMRU.ts` not found

## Not Proven By This UAT

- Integration with CommandPalette UI (S03)
- Integration with app command registry (S02)
- localStorage persistence in a real browser environment (covered by liveStorage guard; localStorage adapter tested with Map mock in vitest)

## Notes for Tester

Both modules are pure — no Electron, no IPC, no browser APIs needed. The injectable storage pattern means vitest runs in node env without jsdom.
