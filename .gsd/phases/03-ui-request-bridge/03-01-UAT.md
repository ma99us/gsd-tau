# S01: Contract Types and BlockerTracker — UAT

**Milestone:** M003
**Written:** 2026-07-20

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: S01 delivers pure TypeScript types and main-process logic with no browser surface. All correctness is fully proven by the Vitest unit test suite (65 tests). No UI or localhost server is involved.

## Preconditions

- Node modules installed (`pnpm install` completed)
- `pnpm test` runner available (Vitest)

## Smoke Test

Run `pnpm test -- blocker-tracker state-machine` and confirm all tests pass with exit 0.

## Test Cases

### 1. BlockerTracker add/remove round trip

1. Run `pnpm test -- blocker-tracker --reporter=verbose`
2. **Expected:** 20 tests pass — add, remove, getAll, size, duplicate-id overwrite, idempotent remove, event emissions all verified.

### 2. SessionStateMachine Waiting transitions

1. Run `pnpm test -- state-machine --reporter=verbose`
2. **Expected:** 45 tests pass — includes Waiting-on-you transitions: Working→Waiting on blocker-added, Waiting→Working on last-blocker-removed with active agent, Waiting→Idle on last-blocker-removed with idle agent.

### 3. Renderer type safety

1. Run `pnpm tsc --noEmit -p tsconfig.renderer.json`
2. **Expected:** Exit 0, no errors — `import type` in shared/types.ts ensures zero runtime @opengsd/contracts import in the renderer bundle.

## Edge Cases

### Duplicate blocker id

- Add a request with id `req-1`, then add another with the same id.
- **Expected:** BlockerTracker overwrites and re-emits; size remains 1.

### Remove non-existent id

- Call `remove('unknown-id')` on an empty tracker.
- **Expected:** No-op; no event emitted; no throw.

### Agent transitions while Waiting

- Inject a blocker (→ Waiting); fire agent_start; fire agent_end; then remove the blocker.
- **Expected:** Final state is Idle (pre-waiting state updated by agent_end while Waiting).

## Failure Signals

- Any Vitest test failure in `blocker-tracker.test.ts` or `state-machine.test.ts`
- TypeScript errors in `shared/types.ts`, `blocker-tracker.ts`, or `state-machine.ts`
- `import type` guard broken: renderer bundle imports runtime code from `@opengsd/contracts`

## Not Proven By This UAT

- IPC serialisation of UiRequestState across renderer boundary (proven in S02)
- Windows toast notification firing (S02)
- Modal rendering (S03)
- End-to-end blocker flow from pi → UI → response (S05)
