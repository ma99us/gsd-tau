**Milestone:** M003
**Written:** 2026-07-20

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All S04 behaviour is covered by vitest unit tests for pure helpers and component logic. The Playwright suite in S05 will provide end-to-end browser-observable verification. Runtime-executable UAT via `npx vitest run` is sufficient for this slice's logic layer.

## Preconditions

- Node modules installed (`pnpm install`)
- Project builds without renderer/ TSC errors

## Smoke Test

Run `npx vitest run renderer/state/modal-queue.test.ts` — all 29 tests green confirms queue helpers are functional.

## Test Cases

### 1. Non-modal methods do not open a modal

1. Inject a `ui-request-added` event with method `notify` into the session store.
2. Observe App.tsx subscription: `handleNonModal` is called, `respondUI` fires with `{ value: '' }`.
3. **Expected:** No modal appears; InlineToast shows the notification text; toast auto-dismisses after 4s.

### 2. Status bar updates for setStatus/setWidget/setTitle

1. Inject `ui-request-added` with method `setStatus` and payload `{ text: "Running…" }`.
2. **Expected:** StatusBar renders "Running…" in the persistent status region below the session header.

### 3. Multiple notify calls stack toasts

1. Inject 3 rapid `notify` events.
2. **Expected:** Up to 3 toasts visible simultaneously; oldest dismissed first on overflow.

### 4. Modal queue depth badge

1. Inject two simultaneous `ui-request-added` events with modal methods (e.g. `confirm`).
2. **Expected:** First modal renders immediately; badge shows "2" on the session tab; answering first immediately shows second; badge disappears when queue empty.

### 5. FallbackModal for unknown method

1. Inject a `ui-request-added` event with method `unknown_future_method`.
2. **Expected:** FallbackModal renders with raw JSON in a read-only code block and a plain text input; Cancel dismisses without error.

## Edge Cases

### Toast overflow

1. Inject 4 rapid `notify` events.
2. **Expected:** Only 3 toasts visible; oldest is dismissed to make room for 4th.

### Empty response for FallbackModal

1. Open FallbackModal for unknown method, submit with empty input.
2. **Expected:** respondUI called with `{ value: '' }` — no validation error.

## Failure Signals

- Any vitest test failure in the 4 S04 test files
- TSC errors appearing in renderer/ files
- Modal appearing for notify/setStatus/setWidget/setTitle/set_editor_text

## Not Proven By This UAT

- End-to-end browser rendering (deferred to S05 Playwright suite)
- Actual Windows toast notification for notify (covered in S02)
- set_editor_text buffering when no EditorModal is open
- Shutdown cancellation clearing the queue (S05)
