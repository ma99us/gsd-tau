# S02: Multi-session SessionManager and Registry Integration — UAT

**Milestone:** M004
**Written:** 2026-07-21

## UAT Type

- UAT mode: runtime-executable
- Why this mode is sufficient: All S02 behaviour is exercised by the Vitest unit test suite (64 tests). There is no browser UI surface introduced in this slice — SessionManager lives in the main process and the restore flow emits an IPC event that will be consumed in S03+. Browser-level verification is deferred to S05.

## Preconditions

- `pnpm install` complete
- No stale dist artifacts required — tests use Vitest with ts-node transforms
- Run from `D:/Projects/gsd-tau`

## Smoke Test

```
pnpm test -- session-manager
```
All 64 tests pass in under 1 second.

## Test Cases

### 1. N-concurrent sessions tracked

1. Open 3 sessions with distinct `cwd` values via `sessionManager.open()`.
2. Call `list()`.
3. **Expected:** Returns 3 `SessionRecord` entries, each with a unique stable `id` prefixed `s_`.

### 2. Close removes from registry

1. Open 3 sessions, close one via `sessionManager.close(id)`.
2. Call `list()`.
3. **Expected:** Returns 2 entries; closed session absent.

### 3. Rename updates registry snapshot

1. Open a session, call `rename(id, 'My Project')`.
2. Call `getRegistry().sessions`.
3. **Expected:** Matching entry has `displayName: 'My Project'`.

### 4. Registry saved on every state change

1. Open a session; spy on `registryStore.save`.
2. Trigger `agent_start`, `agent_end` events on the SessionHandle.
3. **Expected:** `registryStore.save` called for each event (debounced flush observed).

### 5. restore() reopens sessions and calls switch_session

1. Seed `registryStore` with 2 entries (one with `sessionFile`, one without).
2. Call `sessionManager.restore()`.
3. **Expected:** Both sessions appear in `list()`; `client.switch_session` called once for the entry that has a `sessionFile`.

### 6. Before-quit flushes registry before closing

1. Open 2 sessions (both running).
2. Simulate `before-quit`; observe `registryStore.flush()` is called before sessions are closed.
3. **Expected:** flush called while both sessions still live; `wasAutoRunning: true` captured for running sessions.

## Edge Cases

### switch_session failure is non-fatal

1. Seed registry with a session whose `sessionFile` points to a missing path; mock `switch_session` to throw.
2. Call `restore()`.
3. **Expected:** Session still appears in `list()` (client is live); `RESTORE_COMPLETE` still emitted.

### Double-close is idempotent

1. Open a session, close it twice.
2. **Expected:** No error thrown; `list()` reflects the session removed after first close.

## Failure Signals

- Any test failure in `session-manager.test.ts` suite
- TypeScript errors in `tsconfig.main.json` scope

## Not Proven By This UAT

- Browser/renderer observation of `RESTORE_COMPLETE` IPC event (S03+)
- Actual pi process spawning and file-system registry reads (S05 Playwright reboot test)
- Tab UI reflecting restored sessions (S04+)

## Notes for Tester

All S02 behaviours are covered by unit tests with injected stubs — no actual pi binary is spawned. The restore deviation (all sessions restored, not only `wasAutoRunning` ones) is intentional and documented.
